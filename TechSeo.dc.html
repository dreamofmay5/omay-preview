크롤링, 색인, 속도, 구조화 데이터까지. 검색엔진과 AI가 사이트를 읽는 통로를 하나씩 점검하고, 개발 담당자가 바로 고칠 수 있는 우선순위로 정리합니다.

전문 컨설팅 상담 받기

네 가지 영역을 점검합니다

콘텐츠가 검색과 AI 답변에 전달되는 길을 앞에서부터 순서대로 봅니다.

① 크롤링 · 색인

로봇이 페이지를 발견하고 저장하는 과정에 막힘이 없는지 봅니다. robots.txt, noindex, 사이트맵, 색인 현황이 대상입니다.

② 사이트 구조

주소 구조, canonical, 내부 링크, 중복 페이지를 봅니다. 같은 내용이 여러 주소로 열리면 신호가 나뉩니다.

③ 속도 · 사용성

Core Web Vitals와 모바일 화면을 점검합니다. 방문자가 느끼는 로딩과 반응이 기준입니다.

④ 구조화 데이터 · 렌더링

JSON-LD 문법과 Entity 연결(@id), 서버 HTML과 자바스크립트 실행 결과의 차이를 확인합니다. 사이트가 “누구의 어떤 페이지인지”를 기계가 이해하도록 돕는 영역입니다.

사용 경험 지표, Core Web Vitals

Google이 “좋음”으로 안내하는 기준입니다. 방문자가 체감하는 세 가지를 숫자로 봅니다.

LCP · 로딩
2.5초 이하

화면의 가장 큰 내용이 나타나기까지 걸리는 시간입니다.

INP · 반응
200ms 이하

버튼을 누르거나 입력했을 때 화면이 반응하는 속도입니다.

CLS · 안정성
0.1이하

로딩 중 화면이 갑자기 밀리거나 흔들리는 정도입니다.

※ 지표와 기준값은 Google의 안내를 따르며 변경될 수 있어 점검 시점의 기준으로 확인합니다. 속도는 사용자 경험과 크롤링 효율에 영향을 주는 요소 중 하나이며, 콘텐츠가 검색어에 적합한지를 대신하지는 않습니다.

점검 항목

01
색인 현황
서치 콘솔·서치어드바이저에서 색인된 페이지, 제외된 페이지, 오류 사유를 확인합니다.
→ 중요한 페이지가 빠져 있지 않은지가 핵심입니다.
02
robots.txt · noindex
의도하지 않은 차단이나 테스트 때 붙인 noindex가 남아 있지 않은지 봅니다.
→ 리뉴얼 직후에 가장 많이 발견됩니다.
03
사이트맵
sitemap.xml의 존재, 제출 상태, 오류와 죽은 주소가 섞여 있는지 확인합니다.
04
상태 코드 · 리다이렉트
404 페이지, 길게 이어진 리다이렉트, 임시(302) 이동이 영구(301)여야 하는 곳을 찾습니다.
05
URL · canonical 정합성
대표 주소를 하나로 정하고 canonical, 내부 링크, 구조화 데이터의 URL이 모두 일치하는지 확인합니다.
→ http/https, www, 끝 슬래시, 파라미터 차이가 대표적입니다.
06
내부 링크 · 고아 페이지
아무 곳에서도 연결되지 않은 페이지와 링크가 끊긴 곳을 찾습니다.
07
중복 콘텐츠
같은 내용의 페이지, 파라미터로 늘어난 주소, 중복 Schema 출력이 있는지 봅니다.
→ SEO 플러그인과 직접 삽입 코드가 겹치는 경우가 흔합니다.
08
모바일 · 성능
모바일에서의 표시, 이미지 용량, 캐시와 스크립트 로딩 방식을 점검합니다.
09
구조화 데이터
Organization, WebSite, WebPage, BreadcrumbList 등의 문법 오류와 @id 연결, sameAs를 확인합니다.
→ 자체 점검 도구 GEO 엔티티 체크로 미리 확인할 수 있습니다.
10
렌더링 방식
핵심 내용과 구조화 데이터가 서버가 보내는 HTML에 들어 있는지, 자바스크립트 실행 후에만 생기는지 비교합니다.

진행 방식

STEP 01

수집 · 진단

색인 현황, 크롤링 상태, 속도 지표, 구조화 데이터를 자동·수동으로 확인합니다.

STEP 02

우선순위 분류

영향과 난이도를 기준으로 High · Medium · Low로 나눕니다.

STEP 03

수정 가이드

개발자에게 그대로 전달할 수 있는 수정 방법과 예시 코드를 정리합니다.

STEP 04

재점검

수정 후 결과를 다시 확인하고, 이후 정기 점검 주기를 정합니다.

주요 산출물기술 SEO 점검 리포트수정 가이드(개발 전달용)재점검 결과

자주 묻는 질문

워드프레스, 자체 제작, 쇼핑몰 모두 점검할 수 있나요?

네. 구축 방식과 관계없이 검색엔진과 AI가 실제로 읽는 결과(HTML, 응답, 색인 상태)를 기준으로 점검하고, 구축 환경에 맞는 수정 방법을 안내합니다.

개발자가 따로 없어도 되나요?

수정 가이드를 개발 담당자나 제작 업체에 그대로 전달할 수 있도록 작성합니다. 필요하면 적용 확인까지 함께 진행합니다.

사이트 속도가 순위에 얼마나 영향을 주나요?

속도는 사용자 경험과 크롤링 효율에 영향을 주는 요소 중 하나입니다. 다만 순위를 좌우하는 유일한 요소가 아니며, 콘텐츠와 검색 의도에 대한 적합성이 먼저입니다.

우리 사이트의 건강 상태를 확인해 보세요

색인, 구조, 속도, 구조화 데이터를 한 번에 점검하고 우선순위별 수정 가이드로 정리해 드립니다.
